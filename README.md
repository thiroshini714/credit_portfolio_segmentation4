# Credit Portfolio Segmentation and Risk Pattern Analysis

Unsupervised learning project (GUVI x HCL) that groups loan borrowers with
similar financial and credit characteristics, compares historical default
rates across the groups, flags unusual borrower profiles, and presents
everything in an interactive Streamlit dashboard.

**Domain:** Finance and Banking - Loan Analytics and Credit Risk Analysis

## Problem statement

Lenders serve borrowers with very different incomes, credit scores,
employment histories and loan needs. This project uses K-Means,
Hierarchical Clustering and DBSCAN to discover borrower segments (income,
FICO score, DTI, loan amount, employment length, loan purpose, home
ownership), then compares historical default rates between segments.
The `Default` outcome is **never** used to form clusters, only to evaluate
them afterwards.

## Dataset

- Name: `loans_granting_model_dataset` (Lending Club loan data), CSV.
- Place the file at `data/raw/loans_granting_model_dataset.csv`
  (the download link is in the project brief PDF).
- Expected information: annual income, DTI, loan amount, FICO score,
  employment length, loan purpose, home ownership, state, issue date and
  default / loan status. Column names are auto-detected (for example
  `annual_inc`, `fico_range_low/high`, `addr_state`, `issue_d`,
  `loan_status`). If detection fails you can map columns by hand, see
  "Column mapping" below.
- **No real data is included.** This QA package includes
  `data/raw/sample_synthetic_loans.csv`, generated by the included synthetic
  data generator so the project can be run immediately. It is artificial,
  not a Lending Club extract. Results from it are not real findings, and both
  the dashboard and generated report identify synthetic runs.

## Setup on Windows with VS Code

1. **Install Python 3.11 or 3.12** from python.org. Tick **"Add Python to
   PATH"** in the installer. (Newer versions such as 3.13 can work, but the
   optional `umap-learn` package depends on `numba`, which sometimes lags
   behind new Python releases. If UMAP fails to install, use 3.11/3.12.)
2. Install **VS Code** and its **Python** extension. Install **Git** from
   git-scm.com.
3. Open the project folder: *File > Open Folder...* and choose
   `credit_portfolio_segmentation`. Open a terminal with *Terminal > New
   Terminal* (PowerShell).
4. Create and activate a virtual environment:
   ```powershell
   py -3.12 -m venv .venv
   .venv\Scripts\Activate.ps1
   ```
   If PowerShell says scripts are disabled, run
   `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` once, then retry.
   (Alternative in Command Prompt: `.venv\Scripts\activate.bat`.)
   In VS Code press `Ctrl+Shift+P`, choose *Python: Select Interpreter* and
   pick the `.venv` one.
5. Install dependencies:
   ```powershell
   python -m pip install --upgrade pip
   pip install -r requirements.txt
   ```
6. If you have the real dataset, copy it to
   `data\raw\loans_granting_model_dataset.csv`. If you do not have it yet,
   you can use the built-in synthetic demo dataset in the Run section below.

No database or environment variables are required: data is read from CSV
and results are stored as files in `outputs/`.

## Run

If you have the real Lending Club CSV, run:

```powershell
python run_pipeline.py --data data/raw/loans_granting_model_dataset.csv
```

If you do not have the real CSV yet, run the built-in synthetic demo instead:

```powershell
python run_pipeline.py --sample --max-rows 5000
```

Then launch the dashboard:

```powershell
streamlit run app.py
```

The dashboard opens at <http://localhost:8501>. The `--sample` option
creates `data/raw/sample_synthetic_loans.csv` if it does not exist and runs
the pipeline on it. The recommended command computes PCA and t-SNE and
attempts UMAP; if UMAP is unavailable, the pipeline records that limitation
and the dashboard explains why the UMAP projection is unavailable. Synthetic
results are for software demonstration only, not real-world credit findings.
The generated report and dashboard identify synthetic runs explicitly.
Running `python run_pipeline.py` with no arguments also uses the real default
CSV when present, or generates the synthetic demo when it is absent.

Useful options: `--max-rows 20000`, `--skip-umap`, `--skip-tsne`.

### Column mapping (only if auto-detect fails)

The pipeline prints which source column was used for each field. If a
required column (loan amount, income, FICO) is not found, or a wrong one
was picked, map it explicitly:

```powershell
python run_pipeline.py --map fico=my_score_column --map default=loan_status
```

### How `default` is derived

Numeric 0/1 columns are used as-is. Text statuses: *Charged Off* and
*Default* = default (1), *Fully Paid* = repaid (0), anything else (for
example *Current*) = outcome unknown and excluded from default rates.

## Methodology (summary)

1. **Cleaning** - duplicates, impossible values (FICO outside 300-850, income <= 0,
   DTI outside 0-100), label normalisation, `emp_length` text to years, dates
   to `issue_year` / `issue_month`, median / mode imputation.
2. **Outliers** - reported with the IQR rule; clustering uses a winsorised
   (1st-99th percentile) copy, anomaly detection uses the uncapped data.
3. **Features** - loan amount, income, DTI, FICO, employment length,
   loan-to-income ratio (log1p where skew > 1, then standard scaling) plus
   one-hot loan purpose and home ownership. Loan ID and `default` are
   excluded. State and issue date are used only for post-clustering
   geographic and trend analysis.
4. **Dimensionality reduction** - PCA (components to reach 90% variance),
   t-SNE and UMAP for 2-D visualisation.
5. **Clustering** - K-Means (k chosen by silhouette, k >= 3), Ward
   Hierarchical (same k), DBSCAN (eps / min_samples grid from k-distance
   quantiles, fitted on PCA space).
6. **Evaluation** - Silhouette, Davies-Bouldin, Calinski-Harabasz, PCA
   explained variance, cluster interpretability, algorithm agreement (ARI).
7. **Default analysis** - default rate per cluster with 95% Wilson intervals,
   lift versus portfolio and a chi-square test.
8. **Anomalies** - DBSCAN noise points and extreme feature values (robust
   z-score).
9. **Dashboard** - Streamlit with 10 pages and interactive controls.

Reproducibility: random seed `42` (see `config.py`); package versions and
parameters are saved to `outputs/tables/run_metadata.json`.

## Streamlit Community Cloud deployment

1. Push the project source to a GitHub repository.
2. For a synthetic demo deployment only, generate the sample and outputs
   locally first, then explicitly include those ignored demo artifacts:
   ```powershell
   git add -f data/raw/sample_synthetic_loans.csv outputs/
   git commit -m "Add synthetic demo data and dashboard outputs"
   git push
   ```
3. In Streamlit Community Cloud, create an app from that repository, select
   `app.py` as the main file, and deploy. The platform installs dependencies
   from `requirements.txt`.
4. Do not force-add real borrower CSV files, loan identifiers, or real-data
   outputs to a public repository. For private or real-data deployment, use an
   appropriately access-controlled environment and its approved data-storage
   process.

Cloud deployment was not executed as part of this QA run. The ZIP includes
precomputed synthetic outputs so the dashboard can be opened after installing
requirements; rerun the pipeline whenever you change the data or code.

## Troubleshooting

| Problem | Fix |
| --- | --- |
| `Dataset not found` | Put the CSV in `data\raw\` or pass `--data <path>` |
| `Required columns could not be detected` | Use `--map canonical=SourceColumn` |
| `streamlit` is not recognised | Activate the virtual environment, then `pip install -r requirements.txt` |
| Dashboard says "Pipeline outputs not found" | Run `python run_pipeline.py --sample --max-rows 5000` if you do not have the real CSV, or run the pipeline with your real CSV |
| UMAP install fails | Use Python 3.11/3.12, or run with `--skip-umap` (the rest still works) |
| Very slow run | Lower `--max-rows` (e.g. 5000) or add `--skip-tsne` |
| `ModuleNotFoundError: src` | Run commands from the project root folder |
| Port 8501 busy | `streamlit run app.py --server.port 8502` |

## Ethical use

Segments describe groups, not people. Cluster membership must not be used on
its own to decide an individual loan, and historical default rates do not
guarantee future behaviour. Loan IDs are removed from the dashboard dataset
(`clustered_borrowers.csv`); only `anomalies.csv` keeps them so flagged loans can be reviewed.

## Limitations

- Clustering uses a random sample (default 10,000 rows) so Hierarchical
  clustering and t-SNE stay fast; change with `--max-rows`.
- Loans without a final outcome are excluded from default rates; recent
  vintages are under-represented in defaults.
- Silhouette scores on mixed numeric / one-hot data are typically modest.
- Cluster names are generated automatically from feature medians and should
  be reviewed by an analyst.
